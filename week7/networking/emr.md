# 데이터 파이프라인 기초: Spark, EMR, Airflow, Databricks

## 1. 문제: 서비스 데이터는 계속 쌓인다

서비스를 운영하면 다양한 데이터가 계속 생성됩니다.

예: - 사용자 로그 - 주문 데이터 - 클릭 데이터

이 데이터는 시간이 지나면 **수십 GB → 수 TB 이상**까지 커질 수 있습니다.

이 정도 규모의 데이터를 **서버 한 대로 처리하면 매우 오래 걸립니다.**

예:

10TB 로그 분석

  방식        처리 시간
  ----------- -----------------
  서버 1대    몇 시간 \~ 하루
  서버 20대   수십 분

그래서 **여러 서버에서 동시에 데이터를 처리하는 분산 처리 방식**을
사용합니다.

대표적인 기술이 **Apache Spark**입니다.

------------------------------------------------------------------------

## 2. Spark: 대용량 데이터를 분산 처리하는 프레임워크

**Apache Spark**는 여러 서버에서 동시에 데이터를 처리할 수 있도록 해주는
**분산 데이터 처리 프레임워크**입니다.

예를 들어 Spark는 다음과 같은 작업에 사용됩니다.

-   로그 분석
-   데이터 집계
-   추천 시스템 데이터 생성
-   머신러닝 데이터 처리

Spark는 작업을 여러 서버에 나눠서 병렬로 처리합니다.

    Spark Job
       ↓
    여러 서버에 작업 분배
       ↓
    각 서버가 동시에 계산

하지만 Spark를 직접 운영하려면 문제가 있습니다.

------------------------------------------------------------------------

## 3. 문제: Spark 클러스터 운영이 어렵다

Spark를 사용하려면 보통 **여러 서버로 구성된 클러스터**가 필요합니다.

직접 운영하려면 다음과 같은 작업이 필요합니다.

-   서버 여러 대 준비
-   Spark 설치
-   클러스터 구성
-   장애 관리
-   스케일링 관리

이런 인프라 운영이 꽤 복잡합니다.

그래서 AWS에서는 **EMR**이라는 서비스를 제공합니다.

------------------------------------------------------------------------

## 4. EMR: Spark 클러스터를 쉽게 실행하는 서비스

**Amazon EMR**은 Spark 같은 분산 데이터 처리 시스템을 **AWS에서 쉽게
실행할 수 있도록 해주는 서비스**입니다.

EMR을 사용하면 Spark 클러스터를 직접 구축할 필요 없이 AWS가 대신
관리해줍니다.

### EMR 기본 구조

    EMR Cluster

    Master Node
       └ 작업 관리 및 스케줄링

    Worker Nodes
       └ 실제 데이터 처리

Spark 작업을 실행하면

1.  Master 노드가 작업을 나눕니다
2.  여러 Worker 노드가 데이터를 병렬로 처리합니다

------------------------------------------------------------------------

## 5. 데이터 작업은 보통 정기적으로 실행된다

데이터 분석 작업은 보통 **한 번만 실행하는 작업이 아니라 정기적으로
실행되는 배치 작업**입니다.

예:

    매일 새벽 3시
    → 로그 분석
    → 통계 테이블 생성
    → 리포트 생성

이런 작업들을 자동으로 실행하고 관리하는 도구가 **Apache
Airflow**입니다.

------------------------------------------------------------------------

## 6. Airflow: 데이터 작업을 자동으로 실행하는 도구

**Apache Airflow**는 데이터 작업을 스케줄링하고 관리하는 도구입니다.

Airflow는 다음과 같은 기능을 제공합니다.

-   작업 스케줄링 (예: 매일 새벽 3시 실행)
-   작업 순서 관리
-   실패 시 재시도
-   전체 파이프라인 관리

그래서 실제 데이터 파이프라인 구조는 보통 이렇게 구성됩니다.

    Airflow
       ↓
    Spark Job 실행
       ↓
    EMR 클러스터에서 데이터 처리

------------------------------------------------------------------------

## 7. Databricks: Spark 기반 데이터 플랫폼

최근에는 **Databricks**라는 플랫폼도 많이 사용됩니다.

Databricks는 Spark 기반 데이터 처리 환경을 **하나의 플랫폼으로 통합**한
서비스입니다.

기존 구조에서는 여러 시스템을 운영해야 합니다.

    Airflow
    Spark
    EMR
    S3

Databricks는 다음 기능을 하나의 플랫폼으로 제공합니다.

-   Spark 클러스터 관리
-   데이터 분석 환경
-   Job 실행 및 관리
-   Notebook 기반 개발 환경

그래서 데이터 팀이 **더 쉽게 데이터 파이프라인을 운영할 수 있습니다.**

------------------------------------------------------------------------

## 8. 전체 구조 정리

정리하면 다음과 같습니다.

  기술         역할
  ------------ -------------------------------
  Spark        대용량 데이터를 분산 처리
  EMR          Spark 클러스터를 AWS에서 관리
  Airflow      데이터 작업 스케줄링
  Databricks   Spark 기반 데이터 플랫폼

실제 데이터 파이프라인 구조는 보통 다음과 같습니다.

    Airflow
       ↓
    Spark Job
       ↓
    EMR Cluster
       ↓
    데이터 처리

------------------------------------------------------------------------

## 한 문장 요약

-   **Spark**: 데이터를 분산 처리하는 엔진\
-   **EMR**: Spark 클러스터를 AWS에서 관리하는 서비스\
-   **Airflow**: 데이터 작업을 자동으로 실행하는 스케줄러\
-   **Databricks**: Spark 기반 데이터 플랫폼
