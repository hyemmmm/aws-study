# 알아두면 좋은 기타 서비스

## 1. 수집한 데이터를 활용하는 서비스 6가지

### 1. 데이터 분석이란
- 수집한 데이터를 분석하고 유용한 정보를 얻는 것  
- 새로운 지식 발견과 의사 결정을 지원하기 위해 저장된 데이터에서 규칙성과 경향성을 찾는 것  
- 빅데이터 분석, 실시간 분석, 데이터를 가공해 시각화하는 것 등 다양한 종류가 있음  

#### 예

**빅데이터 분석**  
스마트시티에서 도시 전역의 교통 센서 데이터를 모아 교통 체증 패턴을 분석하는 것  

**실시간 분석**  
배달 서비스에서 주문이 갑자기 많이 들어오는 지역을 실시간 분석해 그 지역에 배달원을 추가 배치하는 것

---

### 2. 데이터 저장

#### 데이터 레이크
- 분석에 사용할 데이터를 담아두는 장소 (Raw Data)
- 기본적으로 **S3** 이용

#### 데이터 웨어하우스
- 가공이 끝난 데이터를 저장해 두는 장소
- **Redshift** (데이터 웨어하우스 서비스) 이용

---

### 3. Amazon Athena
- 표준 **SQL**을 사용해 **S3에 저장된 데이터를 간편하게 분석**할 수 있는 대화식 쿼리 서비스
- https://docs.aws.amazon.com/athena/latest/ug/step-1-create-a-database.html
- 기본 사용 흐름
  1. **Create a database**  
     Athena에서 사용할 **테이블들을 묶어 관리할 공간(database)**을 생성한다.  
     Athena의 database는 실제 데이터를 저장하는 DB가 아니라 **테이블 정의를 관리하는 논리적 그룹**이다.
  2. **Create a table**  
     S3에 있는 데이터 파일을 **어떤 구조로 읽을지(table)** 정의한다.  
     즉, 컬럼 구조와 구분자 등을 지정하여 **S3 데이터를 SQL 테이블처럼 조회할 수 있게 만든다.**
  3. **Query data**  
     생성한 테이블을 대상으로 **SQL을 실행하여 S3에 저장된 데이터를 조회한다.**

---

### 4. AWS Glue
- **ETL 처리 (Extract, Transform, Load)** 를 간단히 자동화하는 서비스
- Glue를 사용하여 데이터 ETL 처리를 하고  
  - 데이터 웨어하우스에 저장하거나  
  - 그대로 데이터 레이크에 저장할 수 있음
- 기본 사용 흐름
  1. **데이터 수집 (Extract)**  
     S3, RDS, DynamoDB 등 다양한 데이터 소스에서 데이터를 가져온다.
  
  2. **Crawler 실행 (스키마 자동 생성)**  
     Glue Crawler가 데이터를 스캔하여 컬럼 구조(스키마)를 자동으로 추론하고  
     **Data Catalog에 테이블 형태로 등록**한다.
  
  3. **ETL Job 생성 (Transform)**  
     Glue Job을 만들어 데이터 변환 로직을 정의한다.  
     예: 컬럼 정리, 데이터 필터링, 포맷 변환(CSV → Parquet)
  
  4. **데이터 저장 (Load)**  
     변환된 데이터를 S3 데이터 레이크나 Redshift 같은 데이터 웨어하우스에 저장한다.

---

### 5. Amazon OpenSearch Service
- AWS 클라우드에서 **OpenSearch 클러스터를 쉽게 사용할 수 있게 해주는 서비스**

**OpenSearch**
- **ElasticSearch 기반 검색 및 분석 엔진**
- 전체 텍스트 검색에 강한 성능을 보임
- 데이터가 등록되면 검색을 빠르게 할 수 있도록 자동으로 인덱스라는 검색 데이터(검색용 구조)를 생성

예  
사용자가 입력한 키워드로 **문서·게시글·상품 같은 텍스트 데이터를 빠르게 검색**

- 인덱스를 직접 참조하는 것 외에도 시각화 도구인 Opensearch Dashboard를 사용해 구문 분석(검색을 위해 단어를 조각내는 것) 가능
  -> 코딩 없이 화면에서 즉석으로 데이터를 쪼개, 원하는 조건으로 검색하고 그래프(시각화)를 만들기 위한 목적

---

### 6. Amazon EMR
- **Apache Spark, Hadoop (분산 처리 프레임워크)** 등을 AWS에서 실행할 수 있게 해주는 관리형 서비스

**분산 처리 프레임워크**
- 분석해야 할 데이터가 방대할 때 여러 컴퓨터로 분산 처리하는 것

---

### 7. Amazon QuickSight
![Amazon QuickSight](https://miro.medium.com/v2/resize:fit:4800/format:webp/0*eeScmYbeh23hMAUR)
- 등록된 데이터를 분석하고 그래프화하는 **데이터 시각화 서비스**
- 데이터를 시각화할 뿐 아니라 기계 학습을 통해 데이터의 특징을 발견하거나 추이를 예상하는 기능도 제공
- **자연어 질의 가능**
- 사용 예
  - 쇼핑몰에서 일별 매출 데이터를 그래프로 분석해 매출 추이 확인
  - 과거 데이터를 기반으로 다음 달 매출이나 사용자 수 증가 추이 예측

---

### 8. Amazon Kinesis
- **실시간 비디오 및 데이터 스트림을 수집, 처리 및 분석 서비스**
- 서버리스 스트리밍 데이터 서비스

#### 주요 서비스
- **Amazon Kinesis Data Streams**  
  대량의 원본 데이터를 프로그램에 전달(데이터 수집)

- **Amazon Managed Service for Apache Flink**  
  전달 받은 데이터를 **실시간으로 분석**

- **Amazon Data Firehose**  
  대량의 데이터를 저장소에 실시간으로 순서대로 **저장**

- **Amazon Kinesis Video Streams**  
  대량의 동영상 데이터를 처리 프로그램에 전달(데이터 수집)

# 3. 시스템 자체를 관리하는 서비스

## 1. 시스템 관리란
서비스를 안정적으로 제공하기 위해 필요한 작업

예
- 응용 프로그램 문제 발생시 대응
- 제로데이 취약점(개발자가 아직 알지 못해 패치가 나오지 않은 상태에서 공격자가 먼저 악용할 수 있는 보안 취약점) 대응
- 정기적인 OS 및 미들웨어 업데이트
- 새로운 기능 추가와 같은 시스템 변경 관리
- 보안 및 상태 모니터링

---

## 2. CloudFormation
- AWS 자원을 **JSON 또는 YAML 형식 파일로 관리하고 구축하는 서비스**
- **재현성이 높아 시스템 관리를 쉽게 해줌**

참고
- CloudFormation으로 만든 자원도 **관리 콘솔에서 수동 변경 가능**

---

### Stack(스택)의 개념
CloudFormation에서 'Stack'은 관리의 최소 단위로, **하나의 설계도(Template)에 의해 생성된 AWS 리소스들의 묶음**입니다.
- **세트 메뉴:** EC2, S3, RDS 등을 각각 생성하지 않고 '스택'이라는 하나의 바구니에 담아 통째로 생성하거나 삭제할 수 있습니다.
- **일괄 관리:** 스택을 삭제하면 그 안에 포함된 모든 리소스가 자동으로 함께 지워져 관리가 매우 편리합니다.

### Create Stack 기본 실행 흐름 (4단계)

1. **Step 1: Create stack (설계도 제출)** 작성한 템플릿 파일(YAML/JSON)을 업로드한다. 이 파일은 "어떤 리소스를 만들 것인가"가 정의된 **인프라 설계도** 역할을 한다.

2. **Step 2: Specify stack details (세부 사항 지정)** 생성할 **스택의 이름**을 정하고, 템플릿 내의 **파라미터(Parameter)** 값을 입력한다. (예: 서버 사양, DB 아이디 등 상황에 따라 변하는 값 결정)

3. **Step 3: Configure stack options (옵션 설정)** 스택 식별을 위한 **태그(Tag)**, 실행 권한(**IAM Role**), 생성 실패 시 이전 상태로 되돌리는 **롤백(Rollback) 정책** 등을 설정한다.

4. **Step 4: Review and create (검토 및 생성)** 모든 설정 값을 최종 확인하고 실행한다. AWS가 리소스를 순차적으로 생성하며, 완료 시 **'CREATE_COMPLETE'** 상태가 된다.

## 3. Amazon CloudWatch
- AWS 서비스의 **지표와 로그를 모니터링하고 시각화하는 서비스**

### 지표 (Metric)
AWS 서비스에서 수집되는 데이터

예
- EC2 CPU 사용률
- 메모리 사용률
- S3 접속 수

### 종류

**표준 지표**
- 기본적으로 자동 수집

**맞춤형 지표**
- 사용자가 직접 등록

### 알림 기능
특정 지표가 임계값을 초과하면

- 사용자에게 알림
- 자동 작업 수행

### CloudWatch Logs
- 로그 감시 기능
- 특정 문자열 포함 시 자동 동작 수행

## 4. AWS Systems Manager(SSM)
- EC2, Linux, Windows 서버 관리 서비스(온프레미스도 가능)
- 여러 서버를 중앙에서 통합 관리하는 도구

### 주요 기능

**Session Manager**
- 보안 그룹 설정 없이 서버 로그인 가능
- SSH로 접속하려면 보안그룹에서 22포트 열어야 하는데, AWS 권한으로 서버 셸에 안전하게 접속하는 기능

**Inventory**
- 서버에 설치된 소프트웨어 목록 확인

**Patch Manager**
- OS 및 미들웨어 패치 관리

**Parameter Store**
- 시스템 환경 변수 저장

**Documents**
- Run Command, Automation, State Manager 실행 작업 정의

**Run Command**
- 원격 명령 실행  
- 단일 Document 실행

**Automation**
- 여러 작업을 자동 실행  
- 여러 Document 순차 실행

**State Manager**
- 서버 상태를 일정하게 유지  
- Document를 정기 실행

## 5. Amazon Code 시리즈
- 응용 프로그램 **소스 코드 관리 서비스 그룹**
- GitHub Actions, Jenkins 같은 **CI/CD 도구 대신 사용 가능**

### 주요 서비스
- **CodeCommit** (코드 저장소)
  - Git 기반 코드 저장소 서비스, GitHub와 유사한 역할
- **CodeBuild** (빌드)
  - 테스트도 가능하고 빌드된 결과물은 S3에 보관
- **CodeDeploy** (배포)
  - EC2, Lambda, 온프레미스 서버 등에 배포 가능
- **CodePipeline** (CI/CD 파이프라인)
  - 코드 변경 → 빌드 → 테스트 → 배포 과정을 자동화할 때 사용
- **CodeArtifact**
  - npm registry 같은 패키지 저장소를 AWS에서 제공하는 서비스
  - 회사 내부 패키지 저장소 용도
- **CodeStart**
  - 2024년에 지원 중단

## 6. 효율적인 관리 서비스 이용
- 최근의 서비스는 업데이트 빈도가 높아 관리해야 할 시스템과 작업 빈도가 증가
- 따라서 관리 서비스를 적절히 이용해 운영의 효율성을 높일 수 있음
